Exercise 7: Movie Search App using React

Due Date: Thursday Oct 16, 2025 11:59 PM

Objective

Re-build the Movie Search App using React. The app should let users search for movies using an API and maintain a persistent watchlist using localStorage. You will use props, useState, useEffect, and React Router.

Requirements (40 points)

The high level requirements are the same as in Exercise 6. There is no starter code. Build the project using Vite as demonstrated in the class. See below for the list of components you need to build.

  • App - defines the routes for your pages.
  • Header - navigation links (Search, Watchlist).
  • SearchPage - handles movie search and displays results.
  • MovieCard - reusable component for displaying movie info.
  • WatchlistPage - shows saved movies from localStorage.

Hints

Search Page (/)

  • Think about how to track the search text and store fetched movies - consider using useState.
  • The API returns movie data; update your state with the search results and render a list of MovieCard components.
  • Pass movie data via props to MovieCard.
  • You may find it helpful to organize your API logic in a small helper function.

Watchlist Page (/watchlist)

  • The watchlist should be loaded from localStorage when the page is opened.
  • Consider using useEffect to run that logic only once when the component mounts.
  • Use useState to manage the list of saved movies.
  • Think about how to keep your component updated when a movie is removed.

Routing

  • Use React Router for navigation between / and /watchlist.
  • The links in Header should update the view without reloading the page.
  • Use Routes and Route inside App.js to define your pages.

Data Persistence

  • Store the watchlist as a JSON array in localStorage.
  • When a user adds or removes a movie, make sure to update both your React state and the stored data.

Layout

  • The focus of this exercise is to learn React. Use the style from exercise 6 as much as possible.

    • Style (10 points)

    There are well-established style guidelines and best practices for React code that help keep your code clean, readable, maintainable, and consistent. Below are few guidelines that are widely followed. Please follow them.

    • Use PascalCase for all component file names and exported function names (e.g., MyComponent.jsx, function MyComponent()).
    • Destructure props in the component function signature for clarity (e.g., function Greeting({ name })).
    • Choose clear and meaningful names for state variables and their setters (e.g., const [count, setCount] = useState(0);).
    • Only call useState and useEffect at the top level in a component — not inside loops, conditions, or nested functions.
    • Always specify a dependency array when using useEffect (e.g., useEffect(() => { ... }, [count]);).
    • Use PascalCase for route component names and keep your Routes definitions clean and readable (e.g., <Route path="/about" element=<About /> />).
    • Keep one component per file if possible.
    • Define event handler functions outside of JSX and above the return statement.
    • Leave a blank line between functions and before return blocks for readability.
    • Export your main component at the end of the file (e.g., export default MyComponent;).
    • Keep your code neat, readable, and organized — consistency is key.
